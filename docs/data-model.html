Публичное представление

Наружу пользователь отдаётся через publicUser(), которая собирает новый объект из трёх полей — username, profile, createdAt. Даже если в записи появятся новые служебные поля, они не утекут в API автоматически: список полей задан явно.

Skill — навык

Живёт в levelUpData.skills. Формат задаёт skills-store.js.

ПолеТипЗначение по умолчаниюСмысл
idstringcrypto.randomUUID() или _abc123xyzИдентификатор; на него ссылается task.xpSkill
namestring"Новый навык"Отображаемое название
levelnumber1Уровень; растёт на 1 за каждые 5 XP
expnumber0Опыт внутри текущего уровня, 0–4 после нормализации
descstring""Описание, показывается под шкалой опыта
defaultbooleanfalsetrue только у стартового «Default Skill»: его нельзя удалить и редактировать

Инварианты

  • В массиве всегда есть ровно один навык с default: true — normalize() добавит его, если потерялся.
  • level ≥ 1, exp ≥ 0; нечисловые значения из повреждённого хранилища заменяются на 1 и 0.
  • После applyLevelUps() всегда exp < 5. Значение больше 5 может существовать лишь на короткий момент между начислением награды и вызовом проверки.
  • id уникален; если поле пустое, normalize() выдаст новый.

Что если навык удалили

completeTask() ищет навык по task.xpSkill. Если такого больше нет, опыт получает первый навык в списке, а игрок видит уведомление «Навык задачи не найден, XP начислено на …». Награда не теряется.

Как параметры уровня вычисляются из его номера

Узлы дерева не хранятся — они целиком выводятся из номера уровня в createLevelNode():

ПараметрФормулаУровень 1Уровень 5Уровень 10
Скорость показа1 + 0.2 × (level − 1)x1.0x1.8x2.8
Время на запоминание4 / speed секунд4.00 с2.22 с1.43 с
Награда10 + 5 × (level − 1)10 XP30 XP55 XP
Длина числа/слова4 + ⌊(level − 1) / 3⌋4 знака5 знаков7 знаков
Тип заданияlevel % 2 === 0 → словочислочислослово

Формат ответов API

Все эндпоинты отвечают JSON одной формы, что упрощает клиентский код: успех проверяется одним полем, текст сообщения всегда пригоден для показа пользователю.

// успех
{ success: true,  message?: string, user?: PublicUser }

// ошибка (400, 401, 404, 409, 429, 500)
{ success: false, message: string }

Правила начисления опыта

EXP_PER_LEVEL = 5 (единая константа в skills-store.js) начисление: skill.exp += награда нормализация: while (skill.exp >= 5) { skill.exp -= 5; skill.level += 1 } примеры: было L1/0 XP + 3 XP → L1, exp 3 (уровень не вырос) было L1/3 XP + 2 XP → L2, exp 0 (ровно один уровень) было L1/0 XP + 7 XP → L2, exp 2 (уровень + остаток) было L1/0 XP + 22 XP → L5, exp 2 (четыре уровня за раз)
Что было до исправления

Раньше проверка выполнялась через if, а не while: награда в 22 XP давала один уровень, а «лишние» 15 XP оседали в поле exp и шкала показывала неверное значение. Теперь единственная реализация правил живёт в SkillsStore.applyLevelUps(), и её же проверяет тест pages #2.
