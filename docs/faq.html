FAQ и глоссарий

Ответы на вопросы, которые возникают при первом чтении кода, рецепты типичных доработок, словарь терминов и карта «где что искать».

Вопросы по устройству проекта

Почему игровые данные не на сервере?

Приложение задумано как личный трекер, который работает без регистрации и без сети. Навыки и задания живут в localStorage, поэтому страницу можно открыть даже файлом с диска. Аккаунт нужен только для профиля на сервере; для переноса прогресса между устройствами есть экспорт и импорт JSON, а эндпоинт PUT /api/me/profile — готовый задел под синхронизацию.

Почему JSON-файл вместо базы данных?

Учебный масштаб: десятки пользователей, никакой аналитики, ноль внешних сервисов для запуска. Файл читается и пишется целиком, запись атомарная. Слабое место — гонка при одновременных регистрациях: между чтением и записью нет блокировки. Как только пользователей станет больше нескольких десятков, стоит взять SQLite.

Почему Tailwind подключён через CDN и только на главной?

Так исторически была написана главная страница, и это позволяет обойтись без сборки. Остальные страницы используют обычный CSS. Плата за удобство: в офлайне главная теряет оформление, в консоли появляется предупреждение о непригодности CDN-сборки для продакшена, а строгий CSP включить нельзя.

Почему инлайновые скрипты, а не отдельные файлы?

Каждая страница самодостаточна и открывается двойным кликом. Общий код уже вынесен — assets/skills-store.js и assets/auth.css. Следующим логичным шагом было бы вынести и скрипт главной, что заодно позволит включить CSP.

Зачем нужен «Default Skill», который нельзя удалить?

Чтобы у приложения всегда был получатель опыта. Если бы список навыков мог опустеть, каждое начисление XP требовало бы отдельной ветки «а если навыков нет». Навык можно переименовать и отредактировать — тогда он перестаёт быть дефолтным, а normalize() создаст новый.

Почему сессия хранит только логин?

Данные пользователя могут измениться, а копия в сессии устареет. Логин — стабильный ключ; по нему /api/me каждый раз читает актуальную запись. Размер куки при этом минимален.

Зачем оставили устаревший POST /register?

Ради обратной совместимости с любым внешним клиентом, который мог им пользоваться. Внутри он вызывает те же обработчики, что и новые эндпоинты, поэтому получает и хеширование, и валидацию, и rate limit.

Практические рецепты

Изменить количество опыта на уровень

const EXP_PER_LEVEL = 5;   // ← поменяйте здесь

Больше нигде править не нужно: главная берёт значение из модуля. Но в разметке блока навыка жёстко пять клеток .exp-square — если ставите другое число, обновите и их.

Изменить сложность тренажёра

const speed = 1 + 0.2 * (level - 1);            // скорость показа
const xpReward = 10 + 5 * (level - 1);          // награда
const digits = 4 + Math.floor((level - 1) / 3); // длина числа/слова
const isWordLevel = level % 2 === 0;            // чередование чисел и слов

Время показа считается как 4 / speed в startTraining().

Добавить поле в навык

  1. Добавьте его в createDefaultSkill().
  2. Добавьте значение по умолчанию в цикл внутри normalize() — тогда старые сохранения подхватят поле автоматически.
  3. Отрисуйте его в renderSkill() и, если нужно, добавьте поле в модальное окно.

Добавить эндпоинт API

app.get('/api/stats', (req, res) => {
  if (!req.session.username) {
    return res.status(401).json({ success: false, message: 'Не авторизован' });
  }

  const users = readUsers();
  return res.json({ success: true, total: users.length });
});

Регистрируйте маршрут до express.static, иначе его может перехватить файл. Придерживайтесь общего формата ответа { success, message? } и добавьте тест в test/server.test.js.

Сбросить свой игровой прогресс

localStorage.removeItem('levelUpData');        // навыки и задания
localStorage.removeItem('memoryTrainerData');  // прогресс тренажёра
location.reload();

Удалить пользователя

Интерфейса для этого нет. Остановите сервер, откройте users.json, удалите нужный объект из массива, сохраните файл и запустите сервер снова.

Возможные направления развития

Синхронизация прогресса

Отправлять навыки на PUT /api/me/profile при каждом изменении и подтягивать их при входе. Серверная часть уже готова и покрыта тестами.

Достижения и статистика

Пункты меню были удалены как нерабочие. Данных для них достаточно: createdAt и completedAt у заданий позволяют строить графики и серии.

Ежедневный сброс заданий

Тип daily сейчас чисто декоративный. Логично сбрасывать completed при смене даты, сравнивая с completedAt.

Точный таймер и уведомления

Считать остаток от Date.now() и добавить Notification API, чтобы сообщение об окончании приходило и при свёрнутой вкладке.

PWA

Манифест и service worker сделают приложение устанавливаемым и полностью офлайновым — локальные CDN-ресурсы для этого всё равно понадобятся.
