Вход и профиль

Две небольшие страницы, которые целиком работают через API: login.html — форма входа и регистрации, userinfo.html — экран профиля. Обе используют общий assets/auth.css.

login.html — вход и регистрация

Одна форма и две кнопки: «Войти» отправляет данные на /api/login, «Зарегистрироваться» — на /api/register. Отдельной страницы регистрации нет намеренно: поля одинаковые, а лишний переход только мешает.

Функции страницы

showMessage(text: string, kind: 'error' | 'success'): void

Пишет текст в строку под формой и переключает класс — красный для ошибки, зелёный для успеха.

setBusy(busy: boolean): void

Блокирует обе кнопки на время запроса, чтобы двойной клик не создал два запроса.

submitCredentials(endpoint: string): Promise<void>
/**
 * Отправляет учётные данные на сервер.
 * Пароль уходит только в теле запроса и нигде не сохраняется на клиенте —
 * состояние входа держит httpOnly-кука сессии.
 */
async function submitCredentials(endpoint) {
  const username = document.getElementById('username').value.trim();
  const password = document.getElementById('password').value;

  if (!username || !password) {
    showMessage('Заполните логин и пароль.', 'error');
    return;
  }

  setBusy(true);
  showMessage('Отправляем данные…', 'success');

  try {
    const response = await fetch(endpoint, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      credentials: 'same-origin',
      body: JSON.stringify({ username, password })
    });

    const result = await response.json().catch(() => ({}));

    if (!response.ok || !result.success) {
      showMessage(result.message || 'Не удалось выполнить запрос.', 'error');
      return;
    }

    showMessage(result.message || 'Готово!', 'success');
    window.location.href = 'userinfo.html';
  } catch (error) {
    console.error(error);
    showMessage('Сервер недоступен. Запустите его командой «npm start».', 'error');
  } finally {
    setBusy(false);
  }
}

Обе кнопки вызывают одну функцию с разным адресом — дублирования логики нет. Блок catch отрабатывает единственный случай, когда fetch бросает исключение: сети нет вообще (например, страница открыта как файл или сервер не запущен). Ошибки уровня HTTP (400, 401, 409) исключений не вызывают и обрабатываются проверкой response.ok.

Что здесь было раньше

Страница вообще не обращалась к серверу. Она вела массив пользователей прямо в localStorage и сохраняла туда пароли в открытом виде:

const userData = { username, password, profile: { level: 1, xp: 0, skills: [] } };
users.push(userData);
localStorage.setItem('users', JSON.stringify(users));
localStorage.setItem('userData', JSON.stringify(userData));

Любой скрипт на странице и любой человек с доступом к DevTools видел пароли всех, кто входил с этого браузера. Тест pages #10 теперь запрещает появление localStorage.setItem в этом файле.

userinfo.html — профиль

Страница ничего не знает заранее: при открытии она спрашивает у сервера /api/me и рисует ответ. Есть три состояния — загрузка, данные пользователя, «вы не авторизованы».

renderRow(label: string, value: unknown): HTMLParagraphElement
/** Безопасный вывод: значения вставляются через textContent, а не innerHTML. */
function renderRow(label, value) {
  const row = document.createElement('p');
  const strong = document.createElement('strong');
  strong.textContent = `${label}: `;
  row.appendChild(strong);
  row.appendChild(document.createTextNode(String(value)));
  return row;
}

Это ключевая функция страницы с точки зрения безопасности: имя пользователя приходит с сервера, но задано другим человеком, поэтому обращаться с ним как с разметкой нельзя. Подробнее — в разделе Безопасность.

renderUser(user: PublicUser): void

Строит блок с логином, уровнем, опытом, списком навыков и датой регистрации, отформатированной через toLocaleString('ru-RU'). Затем показывает ссылку «Выйти». replaceChildren() заменяет содержимое одним вызовом, без ручной очистки.

renderMessage(text: string): void

Отрисовывает сообщение и ссылку «Перейти ко входу» — для случаев «не авторизован» и «сервер недоступен».

loadUser(): Promise<void>
const response = await fetch('/api/me', { credentials: 'same-origin' });

if (response.status === 401) {
  renderMessage('Вы не авторизованы.');
  return;
}
if (!response.ok) {
  renderMessage('Не удалось получить данные пользователя.');
  return;
}

const result = await response.json();
renderUser(result.user);

401 обрабатывается отдельно от прочих ошибок: это не сбой, а нормальное состояние гостя, и сообщение для него дружелюбное.

Выход

document.getElementById('logoutLink').addEventListener('click', async (event) => {
  event.preventDefault();
  try {
    await fetch('/api/logout', { method: 'POST', credentials: 'same-origin' });
  } catch (error) {
    console.error(error);
  }
  window.location.href = 'index.html';
});

Даже если запрос не прошёл, пользователь всё равно уходит на главную — интерфейс не должен «залипать» из-за сетевой ошибки.
