Тесты и CI

19 автотестов без единого фреймворка: только встроенный node:test и jsdom. Девять проверяют API, десять — реальные страницы с исполнением их скриптов. Ниже каждый тест по отдельности.

Запуск

npm test                              # все 19 тестов
node --test test/server.test.js       # только API
node --test test/pages.test.js        # только страницы
node --test --test-name-pattern="XSS" test/*.test.js   # по имени
# tests 19
# pass 19
# fail 0
# duration_ms 4267

Почему без Jest

Ноль лишних зависимостей

node:test встроен в Node 18+. Единственная dev-зависимость — jsdom, и та нужна только для тестов страниц.

Скорость

Полный прогон около четырёх секунд, без прогрева трансформеров и без конфигурации.

Соответствие проекту

В приложении нет сборки и нет транспиляции — тестам они тоже не нужны.

test/server.test.js — API

Стенд поднимает настоящее приложение Express на случайном порту и ходит в него обычным fetch. Ключевой приём — изоляция хранилища:

// Изолированное хранилище: тесты не должны трогать реальный users.json.
const tmpUsersFile = path.join(fs.mkdtempSync(path.join(os.tmpdir(), 'sl-test-')), 'users.json');
process.env.USERS_FILE = tmpUsersFile;
process.env.SESSION_SECRET = 'test-secret';
process.env.BCRYPT_ROUNDS = '4';

const app = require('../server.js');

test.before(async () => {
  await new Promise((resolve) => { server = app.listen(0, '127.0.0.1', resolve); });
  baseUrl = `http://127.0.0.1:${server.address().port}`;
});

test.after(() => {
  server?.close();
  fs.rmSync(path.dirname(tmpUsersFile), { recursive: true, force: true });
});

Переменные окружения выставляются до require('../server.js') — иначе модуль прочитал бы значения по умолчанию. Порт 0 означает «любой свободный», поэтому тесты не конфликтуют с запущенным сервером разработки. Стоимость bcrypt снижена до 4 ради скорости.

test/pages.test.js — страницы в jsdom

Эти тесты не читают HTML как текст (хотя есть и такие проверки) — они исполняют скрипты страниц в настоящем DOM. Благодаря этому любая ошибка вида «функция не определена» ломает сборку.

Тонкость: почему ответ читается из DOM

Переменные страниц объявлены через let и не становятся свойствами window — обратиться к window.currentNumber нельзя ни в браузере, ни в jsdom. Зато объявления function в window попадают, поэтому window.startTraining() и window.checkAnswer() вызываются напрямую, а «загаданное» значение тест читает из элемента #numberDisplay — ровно так же, как его видит пользователь.

Непрерывная интеграция

name: CI

on:
  push:
    branches: ['**']
  pull_request:

jobs:
  test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node-version: [18.x, 20.x, 22.x]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node-version }}
          cache: npm
      - run: npm ci
      - run: npm test
  • Матрица версий — тот же код проверяется на Node 18, 20 и 22: минимально поддерживаемой, предыдущей LTS и текущей.
  • npm ci, а не npm install — строгая установка ровно из package-lock.json.
  • cache: npm — кеширование зависимостей между запусками.
  • Триггеры — любой push в любую ветку и каждый pull request.

Чего тесты не покрывают

  • Визуальную часть: CSS, анимации, адаптивность — jsdom не занимается версткой и рендерингом.
  • Работу таймера на главной: он завязан на реальное время и setInterval.
  • Перетаскивание дерева: события мыши и касаний в jsdom эмулируются неполно.
  • Реальную работу rate limit: тест потребовал бы 21 запроса и заметно замедлил бы прогон.
  • Кросс-браузерность: проверяется только среда jsdom.

Как добавить свой тест

test('описание того, что проверяем', async () => {
  const res = await api('/api/…', {
    method: 'POST',
    body: JSON.stringify({ /* … */ }),
  });
  const body = await res.json();

  assert.equal(res.status, 200);
  assert.equal(body.success, true);
});
test('index.html: описание', async () => {
  const window = await loadPage('index.html');   // упадёт при любой ошибке JS

  window.addNewSkill();                          // функции доступны напрямую

  const stored = JSON.parse(window.localStorage.getItem('levelUpData'));
  assert.equal(stored.skills.length, 2);
});

Файл достаточно положить в test/ с именем *.test.js — скрипт npm test подхватит его автоматически.
